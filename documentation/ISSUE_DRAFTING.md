# Draft a GitHub issue with an agent

Use this procedure for `HHS/simpler-grants-pdf-builder`. The contribution and triage guides govern issue content and labels.

1. **Screen the input before external calls.** Keep credentials, personal details, and restricted NOFO content out of searches, drafts, attachments, and links. Check filenames, screenshots, and URLs as well as prose. If you mention that you omitted a sensitive detail, describe its category without repeating the value in progress messages, screening notes, or the final response. Use generic symptoms for searches. For a suspected vulnerability, stop the public issue workflow and direct the contributor to [HHS responsible disclosure](SECURITY.md).
2. **Read the upstream sources.** Read the templates, [issue labels](CONTRIBUTION_WORKFLOW.md#issue-labels), and [triage guide](QUALITY_REVIEW_AND_TRIAGE.md#review-finding) from upstream `main`, using a GitHub reader or fetching upstream `main` and reading files with `git show`. For bugs use `.github/ISSUE_TEMPLATE/bug_report.md` (`Bug 🐛`). For features use `.github/ISSUE_TEMPLATE/feature_request.md` (`Feature request`). For documentation use the feature template with `documentation` in place of its default label.
3. **Check labels and duplicates.** Use the upstream GitHub integration or `gh label list --repo HHS/simpler-grants-pdf-builder --limit 100` (raise the limit if reached) and `gh issue list --repo HHS/simpler-grants-pdf-builder --state all --search "<sanitized keywords>"`. Surface a matching issue before drafting a new one. Link related issues in the draft. If a source or lookup is unavailable, identify the unchecked item and mark the draft provisional. Apply only verified labels and resolve provisional checks before automated posting.
4. **Draft and review.** Preserve template headings and order. Follow [finding guidance](QUALITY_REVIEW_AND_TRIAGE.md#review-finding) and [assisted review guidance](QUALITY_REVIEW_AND_TRIAGE.md#review-assisted). Distinguish observations from suspected causes and mark unperformed checks as such. Record only actions the contributor reported or you observed as actual reproduction steps. Label any proposed steps as suggested and mark unknown actions as unconfirmed. Separate [proposed priority and rationale](QUALITY_REVIEW_AND_TRIAGE.md#review-priority) from labels to apply until the triager confirms it. Before returning or posting the issue, check template conformance, evidence, duplicate status, and public safety. If the contributor asks to see a draft or their intent to file is unclear, return the draft.
5. **File when asked.** A request to file or post the issue authorizes submission after the checks above. If the contributor asks to see a draft first, wait until they ask you to post it. Use the GitHub integration or authenticated `gh issue create` with the explicit upstream repository. Return the issue link if created, even if some labels still need to be applied. For a definitive failure, hand over the draft. After a timeout or other ambiguous result, look for a matching issue before offering another submission path. If still uncertain, report the uncertainty and hold any retry or filing link.
6. **Hand over when manual filing is needed.** Provide the copyable title and Markdown body, with labels listed separately for a triager. Link to upstream `/issues/new?template=<basename>` with the encoded template basename. Optionally prefill the encoded title and body if the final URL is at most 8,000 characters. Otherwise use the short template link. Keep sensitive details out of the URL and flag any template label that needs replacing.
